# LexPro 当前功能完成情况与 MCP 能力说明

> 更新日期：2026-08-11  
> 本文用于说明当前主要业务流程的完成情况，以及现阶段 MCP 已具备的能力。

## 一、主要业务流程

### 1. 已完成部分

#### 用户认证与权限管理

- 支持用户登录、JWT 身份认证和退出。
- 支持查询当前登录用户及其角色、权限和所属组织。
- 支持管理员查询用户列表和用户详情。
- 支持管理员创建用户、启用或禁用用户以及重置用户密码。
- 支持角色、权限目录和组织树查询。
- 支持按照案件承办人、审核人和协作者控制案件访问。
- 关键操作会写入审计日志。

#### 案件管理

- 支持案件创建、分页查询、条件筛选、详情查看和信息修改。
- 支持当事人信息管理。
- 支持承办人、审核人和协作者的分配及历史记录查询。
- 支持案件级读取、编辑和管理权限校验。
- 支持办理期限和逾期状态计算。

#### 电子卷宗管理

- 支持文件上传、下载、重命名、分类和软删除。
- 支持文件夹和标签管理。
- 支持记录文件哈希、大小、类型和上传信息。
- 对外响应不会暴露存储路径、内部对象键等敏感信息。

#### 文档解析基础流程

- 支持异步解析任务、任务状态查询和失败重试。
- 支持解析结果版本管理和历史查询。
- 当前支持 UTF-8 编码的 `.txt` 文件解析。
- 已实现队列限制、文本长度限制和异常状态记录。

#### 文书实体识别

- 使用 DeepSeek/OpenAI 兼容接口识别实体。
- 支持人员、组织、地点、日期、金额、案号和法律引用等实体类型。
- 校验实体文本必须能够在原始材料中找到。
- 保存模型原始结果、模型信息、Token 用量和请求信息。
- 支持人工修改后的首次确认。
- 真实 DeepSeek 调用已经测试通过。

#### 法律要素识别

- 支持主体、主观方面、客体、客观方面、事实、证据、法律依据和争议焦点等通用要素。
- 每个法律要素必须保留对应的原文证据。
- 支持置信度和原文位置校验。
- 支持人工修改和首次确认。

#### 案件摘要

- 支持事实、过程、结论和完整摘要四类摘要。
- 支持选择同一案件下的多份解析材料生成摘要。
- 支持异步生成、版本历史和当前版本管理。
- 生成失败时会保留上一个成功版本。
- 支持人工确认。

#### 典型案例推荐

- 支持典型案例导入和标准化。
- 支持使用本地 BGE-M3 模型生成向量。
- 支持结构化过滤、全文检索和向量检索。
- 支持 RRF 融合、结果重排和推荐理由生成。
- 支持推荐历史、推荐详情和收藏管理。
- Python 检索服务使用受限的只读数据库权限。

#### 案卡回填

- 支持根据文档、实体、法律要素和摘要生成案卡字段。
- 案卡字段保留来源、原文位置和置信度。
- 支持逐字段确认或驳回。
- 所有字段处理完成后可以确认整个案卡。

#### 审查报告

- 支持报告模板创建、查询、启用和停用。
- 支持根据案件材料和智能分析结果生成报告。
- 支持报告草稿编辑、提交审核、退回和定稿。
- 支持 DOCX 和 PDF 导出。
- 报告关键内容保留来源引用。

### 2. 未完成或部分完成

#### 组织和权限配置管理

- 后端当前只提供组织树查询，尚未提供组织新增、编辑、启停和层级调整能力。
- 尚未提供人员同步能力。
- 尚未提供现有用户的角色和所属组织调整能力。
- 尚未提供角色新增、编辑以及角色权限分配能力。

#### 多模态文档解析

- 尚未支持 PDF、Word、PNG、扫描件和 OCR 正文解析。
- 尚未实现询问笔录“问-答”结构恢复。
- 尚未实现跨页、跨段落的版面和语义恢复。
- 当前上传这些格式后不能进入完整的智能分析流程。

#### 实体识别验收

- 尚未建立正式的标注测试集。
- 尚未证明实体识别准确率达到 95%。
- 尚未完成长文本、批量文档和多模态识别验收。

#### 法律要素体系

- 当前只有 9 类通用法律要素。
- 尚未建立刑事、民事、行政和公益诉讼四套差异化要素体系。
- 尚未达到刑事案件不少于 60 个识别要素的要求。
- 尚未证明法律要素识别准确率达到 90%。
- 尚未实现根据不同罪名自动切换要素模板。

#### 案件摘要能力

- 尚未提供直接编辑摘要正文的能力。
- 尚未实现要点简报式、案例类比式等独立摘要模式。
- 尚未提供摘要独立导出功能。
- 尚未验证 10 秒内完成生成的性能目标。

#### 人工反馈与模型优化

- 已保存人工确认结果，但尚未形成正式训练数据集。
- 尚未实现人工修正结果进入增量训练或模型优化流程。
- 尚未提供模型效果评估和版本对比功能。

#### 典型案例推荐验收

- 地域、文书类型、案例来源和适用法条等过滤条件尚不完整。
- 尚未完成 TB 级案例库性能测试。
- 尚未证明推荐置信度达到 80%。
- 尚未完成生产规模下 10 秒响应目标的验收。

#### 系统管理

- 模型配置目前主要依靠环境变量。
- 尚未提供可持久化管理模型接口配置的后端能力。
- 已记录关键操作日志，但尚未提供完整的审计日志查询和管理能力。
- 当前只有基础健康检查，尚未提供完整的运行指标、告警和监控能力。
- 案件、知识内容和工作任务的部分状态流转规则尚未确认。

#### 生产交付

- 尚未接入生产对象存储或 MinIO。
- 尚未完成恶意文件检测。
- 尚未完成备份恢复演练、生产部署、TLS、监控和生产压力测试。

## 二、MCP 已完成能力

### 1. 统一、安全的查询入口

MCP 已提供统一的访问入口，使兼容 MCP 的客户端能够使用当前 LexPro 用户身份查询系统数据。客户端必须完成身份认证后才能使用相关能力，未认证请求会被拒绝。

### 2. 当前用户信息查询

MCP 可以查询当前登录用户的基本信息、所属组织、系统角色和权限列表。该能力可以帮助客户端判断当前用户是谁，以及后续能够使用哪些查询能力。

### 3. 授权案件搜索

MCP 可以搜索当前用户有权查看的案件，并支持分页、关键词、案件状态、案件类型和逾期状态等筛选条件。查询结果会遵守现有案件权限规则，普通用户不能借助 MCP 查看未授权案件。

### 4. 授权案件详情查询

MCP 可以查询一个具体案件的允许字段，包括案件基本信息、状态和办理相关信息。即使客户端知道案件编号，只要当前用户没有案件访问权限，系统仍会拒绝返回案件数据。

### 5. 卷宗文件元数据查询

MCP 可以查询授权案件下的卷宗文件列表，包括文件名称、文件类型、文件大小、上传人员、上传时间和标签等信息。该能力只提供文件元数据，不会返回文件正文、文件哈希、内部存储路径、对象存储键或删除信息。

### 6. 类案推荐历史查询

MCP 可以查询授权案件已经产生的类案推荐历史，包括推荐记录、使用的模型和检索流程版本、创建时间及执行耗时。该能力用于查看已有结果，不会发起新的推荐任务。

### 7. 类案推荐详情查询

MCP 可以查询某次类案推荐的详细结果，包括推荐的典型案例、排名、分数、推荐理由和案例基本信息。返回结果不会包含原案件的完整事实文本、争议焦点快照、查询向量、内部检索参数或内部请求信息。

### 8. 权限和案件边界控制

所有 MCP 查询都会使用当前用户的真实角色和权限，并继续执行案件级访问校验。MCP 不会绕过现有业务服务，也不会形成独立于 LexPro 权限体系之外的数据通道。

### 9. 输入、输出和运行限制

MCP 已对输入参数进行严格约束，不接受未定义参数，并限制单次查询的返回数量、输出长度和执行时间。非法参数、超出权限的请求和异常调用会返回稳定、可识别的错误结果。

### 10. 敏感数据过滤

MCP 在返回数据前执行字段白名单和敏感信息过滤。卷宗存储信息、内部路径、原案件私有查询文本、内部参数和其他不应暴露的数据不会出现在结果中。

### 11. 操作审计

每次 MCP 工具调用都会记录调用用户、关联案件、调用能力、执行结果和请求标识。审计记录不会保存完整的客户端输入，从而兼顾安全追踪和敏感数据保护。

### 12. 当前能力边界

现阶段 MCP 定位为只读查询能力，不提供文件正文读取、数据新增、修改、删除、智能任务发起、结果确认或系统管理操作。MCP 本身也不包含 AI 模型和聊天页面，需要由兼容 MCP 的客户端或后续 AI 助手使用这些能力。
