# M2 认证安全审查

[English](../M2_SECURITY_REVIEW.md)

> 审查日期：2026-07-29
> 范围：认证、用户管理、组织/RBAC 查询和前端会话处理。

## 已实现控制

- 只有健康检查、本地接口文档和登录公开；其他 API 路径都要求认证。
- 用户、组织、角色和权限管理在控制器方法边界要求 `USER_MANAGE`。
- 每个受保护请求都会检查 HS256 签名、issuer、过期时间、当前账号状态、账号更新时间和数据库中的当前权限。
- 密码使用 BCrypt，cost 为 12。新建或重置密码至少 12 个字符，包含大小写字母、数字和特殊字符，并限制为 72 个 UTF-8 字节。
- 未知用户、密码错误和账号禁用统一返回 `INVALID_CREDENTIALS`。虚拟 BCrypt 比较降低用户名计时差异。
- 登录成功/失败、退出、初始化管理员、创建用户、修改状态和重置密码都会写审计，审计不包含密码或 Token。
- 登录失败审计使用独立事务，避免被最终抛出的 401 回滚。
- DTO 和前端状态不包含密码哈希。认证响应使用 `Cache-Control: no-store`。
- 开发管理员初始化默认关闭，只在没有任何用户时运行，并且不记录密码。
- 前端已删除硬编码凭据，在进入路由前检查 JWT 过期时间，并在 API 返回 401 时清理会话。

## 明确保留的限制

- 没有 Refresh Token 或服务端 Token 黑名单。退出由客户端失效和审计组成；复制出的 Token 在账号未变更时可使用到自然过期。
- Access Token 保存在 Web Storage。默认使用 `sessionStorage`；选择“保持登录状态”时使用 `localStorage`，因此仍必须重视 XSS 防护。
- HS256 使用一个应用共享密钥。生产环境必须通过部署配置注入唯一高熵密钥并进行轮换。
- 当前没有登录限流和账号锁定，因为尚未批准代理或限流基础设施。系统对互联网开放前，生产部署必须提供边缘限流。
- M2 施工没有修改现有开发数据库。首个管理员仍需经过明确启用的一次性初始化。

## 验证证据

- 后端单元和 MVC 测试覆盖 BCrypt、安全初始化、统一登录失败、JWT Claims、401/403 `ProblemDetail`、用户管理、审计内容、组织循环和应用上下文。
- Maven 全量测试和后端打包通过。
- 前端 JavaScript 语法检查和 Vite 生产构建通过。
- 在用户明确批准写入首个开发管理员前，真实登录 HTTP 冒烟测试仍是人工步骤。
